# Task 1 behavioral-baseline capture — fresh review

Task 1 adds a Playwright-based evidence pipeline that captures the current portfolio's ten routes and the public reference's seven milestones across five viewport/preference states, then renders a paired ignored HTML index and two markdown reports. This pass re-reviews the complete working tree against `23ac2fe`, including untracked files, after a prior review (`2026-07-21-031138-review.md`) flagged four issues: unverified silent paths marked safe, a mislabeled mobile Home overlay, a non-comparative index, and unmasked volatile Blog content. All four are demonstrably fixed in the current code and generated evidence. **Watch for:** **confirmed** the Blog masking fix is incomplete — a live "glitch" heading and an unmasked random paragraph still leak into both screenshots and the manifest in most states; **confirmed** the new scripts/tests sit outside `tsconfig.json`'s `include`, so `npm run build` never type-checks them, and `capture-current.ts` would fail to compile under the project's own ES2020 lib target if it did; **confirmed** the reference `desktop-sound-gate` state produces byte-identical evidence to `desktop-pointer` for every subject, despite being documented as distinct "entry/audio-gate evidence."

## High-level view

The audio-safety model now distinguishes `verified`, `blocked`, and `unsafe` and binds every audit to the state it ran in, closing the prior "blocked paths reported as safe" gap. Entry completion is verified by hit-testing that the gate no longer intercepts input and that a post-entry control is reachable, so the mobile Home artifact is now correctly `blocked` rather than passed off as captured evidence. Destination changes for Index, Work/project, and About are confirmed by diffing visible headings, regions, controls, and URL/title before and after activation, with a second confirming read to reject transient DOM churn. `writeBaselineIndex` now renders one comparison section per state/milestone pair with explicit current-side gap cards, fixing the prior "adjacent, not comparative" index.

The Blog-redirect masking fix only partly holds: it correctly hides the visible clock everywhere, but the target page runs a continuously regenerating glitch-text effect on its archival heading (plus an adjacent random paragraph the mask never targets at all), so the one-shot DOM mutation gets overwritten by the time the observation and screenshot happen in three of the four states that hit that route.

The reference capture correctly restricts itself to an explicit, ancestor-validated silent-entry control and audits audio from a true pre-click snapshot through a terminal post-traversal snapshot, including delayed activity, later milestones, cross-frame history, and full-document navigation, backed by dedicated adversarial fixtures. Its main gap is that `desktop-sound-gate`, unlike its `current`-target counterpart, isn't special-cased at all: it runs the identical silent-path traversal as `desktop-pointer` with the same viewport and input, producing duplicate artifacts and duplicate (mis-titled) evidence.

The new automation code lives entirely outside the TypeScript project's compiled surface: `tsconfig.json` only includes `src`, so `tsc -b` (the type-check half of `npm run build`) never sees `scripts/`, `tests/`, or `playwright.config.ts`. Playwright's own transform runs untyped code without complaint, and the gap isn't hypothetical — `capture-current.ts`'s `escapeHtml` uses `String.prototype.replaceAll`, which needs `lib: ["ES2021", ...]`, while the project's actual `lib` is `ES2020`.

The dependency change itself is clean: `@playwright/test` is pinned to exactly `1.61.1` in both `package.json` and the lockfile, with `playwright`/`playwright-core` reconciled to the same version. The large unrelated deletions in `package-lock.json` are `npm install` pruning a stale `gh-pages`-rooted subtree that was never declared in `package.json`, even at the base commit — a beneficial side effect, not scope creep.

## Findings

**Critical:** none.

**Important:**

1. **Incomplete Blog volatility normalization** — `normalizeVolatileCurrentContent` (`scripts/reference/capture-current.ts:255-286`) masks the visible clock everywhere and rewrites `h1/h2/h3` text matching `/^ARCHIV/i` to a placeholder, but only when `subjectId === 'blog'`. **confirmed** by direct evidence: `artifacts/baseline/current/desktop-pointer/blog.png` shows the clock masked but the archival heading rendering live, unmasked glitch text ("ARCHIVAL AZD}:CX<R AFO[UZCV7 XGVGH:6 Y4"), plus a fully unmasked randomized paragraph beneath it that the mask never targets. `artifacts/baseline/current/manifest.json`'s `desktop-keyboard/blog` record carries a *different* unmasked heading ("ARCHX#25 B8LBL8!!0...") whose first four characters don't even match the `/^ARCHIV/i` prefix, because the target's own glitch effect randomizes its prefix between renders. Only `mobile-touch/blog` got the intended `[MASKED DYNAMIC HEADING]` placeholder, by timing rather than by design. Failure scenario: anyone using this baseline to judge "what the current Blog handoff looks like" sees a different random string each time and may mistake site-generated noise for a real design element, or conclude the masking works when it demonstrably doesn't for 3 of 4 desktop-adjacent states.
2. **New automation code isn't in `tsc`'s type-check scope, and one file wouldn't compile if it were** — `tsconfig.json`'s only `include` is `["src"]` (verified by reading the file), so `scripts/`, `tests/`, and `playwright.config.ts` are never type-checked by `npm run build`. **confirmed** by re-running the project's exact `compilerOptions` with `include` widened to cover `scripts/`/`tests/`: `scripts/reference/capture-current.ts(64,6): error TS2550: Property 'replaceAll' does not exist on type 'string'. ... Try changing the 'lib' compiler option to 'es2021' or later.` `escapeHtml` (lines 61-68) chains five `.replaceAll(...)` calls, which need ES2021 lib; the project's `lib` is `ES2020`. Nothing breaks at runtime (Node 22 and Chromium both support `replaceAll` regardless of the TS `lib` setting), but the reported "build passed" validation gives zero assurance about these files, and this exact class of mismatch went undetected until now.
3. **Reference `desktop-sound-gate` duplicates `desktop-pointer`** — `createCapturePlan`'s gap logic (`tests/fixtures/viewports.ts:117-140`) is `input.target === 'current' && state.soundGate`; for `target: 'reference'` the `soundGate` flag changes nothing, and `captureReferenceBaseline` has no branch that treats it specially. **confirmed**: `artifacts/baseline/reference/manifest.json` shows `desktop-sound-gate` and `desktop-pointer` producing identical `audioContextResumeAttempts`/`runningAudioContexts` values, identical `unsafe` classification with the identical reason string, and identical destination URLs/`scrollHeight` for every subject. `docs/reference/behavioral-baseline.md`'s coverage table describes this state's purpose as distinct "Entry/audio-gate evidence," but none of the captured evidence is specific to the sound gate. Failure scenario: a reviewer using the baseline index to compare "sound gate" behavior against "pointer" behavior side by side will see two identical columns and may wrongly conclude the reference gate was actually audited under a sound-choice-adjacent condition, when it's a second identical run of the silent path.

**Minor:**

1. **Baseline captured against `vite dev`, not a production preview build** — `playwright.config.ts`'s `webServer.command` is `npm run dev -- --host 127.0.0.1 --port 4173`. **possible**: dev-mode-only behavior (HMR, unminified bundles) could diverge from what real visitors see; the font-load failures and Three.js buffer-resize errors already recorded in the manifest are dev-server console output and haven't been checked against a `vite build && vite preview` run. Would need a comparison capture against `preview` to confirm any divergence.
2. **Sound-gate duplication isn't disclosed in the docs** — `docs/reference/interaction-inventory.md` notes "`desktop-sound-gate` names the audit state, not the selected choice," but doesn't say the resulting evidence is otherwise byte-identical to `desktop-pointer` (see Important #3). A one-line callout would prevent a reviewer from double-checking evidence that's already known to be redundant.

## Spec-compliance verdict

The implementation satisfies the binding requirements in `.superpowers/sdd/task-1-brief.md`: all required files exist, Playwright is pinned at exactly `1.61.1` with a reconciled lockfile, the current-site sweep covers all ten routes across all five states with unique artifact paths and explicit sound-gate gaps, the reference sweep never activates a sound-enabled control (enforced by ancestor-validated label matching and a muted browser process, backed by adversarial fixtures), unreachable states are recorded as explicit `blocked`/`gap` evidence rather than fabricated captures, the comparison index pairs current/reference evidence with gap slots, `.superpowers/` and generated artifacts are gitignored and never staged, and both docs' quantitative claims (40 captured/10 gap current; 20 captured/15 blocked reference; stale reference `generatedAt`) match the generated manifests exactly. The remaining gaps are evidence-quality issues within Task 1's own stated goals, not missed requirements: the Blog volatility-masking claim is incomplete against the live target, and the `desktop-sound-gate` reference state doesn't deliver the distinct audit its own documentation implies.

## Code-quality verdict

The core audit and destination-verification logic — the audio state machine, entry-completion hit-testing, milestone predicates, and ancestor-bubbling label safety — is well-factored and backed by genuinely adversarial fixtures rather than happy-path-only tests. The two Important findings above are contained, not systemic: the volatility-masking approach is too literal for a live, self-randomizing target and needs a settle-then-mask or content-shape-based strategy instead of a one-shot prefix regex, and the new files' exclusion from `tsc`'s `include` means a real type-safety gap has already gone undetected through the stated "build passed" validation. Neither is a regression introduced by this diff turning previously-correct code incorrect; both are gaps in what the existing validation actually covers. The lint failure is confirmed pre-existing (no `eslint.config.*` anywhere in the repo, matching the brief's stated Task 2 handoff) and is not worsened by this change.
