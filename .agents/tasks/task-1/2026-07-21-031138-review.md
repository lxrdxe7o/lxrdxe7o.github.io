# Current and reference behavioral baseline capture

Task 1 adds Playwright baseline capture for ten current routes and seven reference milestones across desktop, mobile, keyboard, reduced-motion, and sound-gate states. It records ignored evidence, explicit gaps or blocked states, and the observed interaction inventory. The reference path is deliberately silent-label-gated and browser-muted, but several result classifications overstate what the run proved. **Watch for:** **confirmed** unverified silent-entry modes are serialized as safe; **confirmed** the mobile Home record is still the entry overlay; **confirmed** the index neither pairs current/reference states nor supplies required current-side gaps; **confirmed** volatile Blog time and randomized text remain in supposedly stabilized evidence.

**Verdict**: NEEDS_CHANGES

## High-level view

Shared fixtures create deterministic subject/state paths, separate runners collect current and public-reference evidence, and both feed one ignored HTML index. Explicit silent-label selection, escaped index values, and blocked records establish the right safety boundary.

**confirmed** The audio audit uses a boolean `safe` result even when no silent path was exercised. Keyboard and reduced-motion runs therefore appear safe despite being blocked at entry.

**confirmed** A successful click is treated as successful entry without proving the gate disappeared. The mobile artifact remains on the Enter overlay but is counted as captured Home evidence.

**confirmed** The index appends all current records before all reference records and omits current-side Loader, Index, project-sequence, and Footer gaps. Its columns are adjacent cards, not the comparisons required by the brief.

**confirmed** Timestamp masking recognizes only semantic selectors. The external `/blog` destination exposes a clock and randomized archival heading outside them, making both screenshot and manifest output volatile.

<summary>Details</summary>

### Blocked silent-entry modes are reported as safe

**confirmed** When no explicit silent control is found, `captureReferenceBaseline` blocks every post-entry subject but calls `evaluateAudioSafety(beforeEntry, beforeEntry)`, producing `safe: true` (`scripts/reference/capture-reference.ts:594-610`). The generated manifest shows blocked Home-and-later records for `desktop-keyboard` and `desktop-reduced-motion` beside positional audit entries claiming `safe: true` and `silentPathAudioDetected: false`.

Only the pre-consent result is known in those modes. The audit should identify its state and distinguish `verified`, `blocked`, and `unsafe`, while preserving automatic-audio status separately. The pointer-only fixture test needs a no-silent-control case asserting an explicitly unverified audit.

### Mobile Home is captured before entry completion

**confirmed** After activating a silent label, the runner waits for network/fonts and immediately captures Home without checking that the gate disappeared (`scripts/reference/capture-reference.ts:613-624`). `reference/mobile-touch/home.png` still shows Enter, while the manifest labels it `subject: home`, `status: captured`; the documentation also concedes that dismissal was not proved.

This artifact should remain entry-transition evidence or become blocked Home evidence. A bounded, source-agnostic completion check should require the gate to stop intercepting input and a stable post-entry control to become reachable; a persistent-overlay fixture should lock in that behavior.

### Evidence index is adjacent, not comparative

**confirmed** `writeBaselineIndex` sends `[...currentRecords, ...resolvedReferenceRecords]` to the card renderer (`scripts/reference/capture-current.ts:295-310`). The generated index therefore completes all 50 current cards before the 35 reference cards; its first row is Current Home beside Current About. It also has no `Current · Loader`, `Current · Index`, `Current · Project sequence`, or `Current · Footer` record despite the documentation promising corresponding evidence or limitations.

The index needs rows keyed by state and behavioral milestone, each with current and reference slots; absent capabilities should render explicit current gap cards. The test at `tests/visual/baseline-capture.spec.ts:142-166` checks only label presence and should assert pair ordering and required gaps.

### Volatile Blog UI survives stabilization

**confirmed** The current runner masks `time`, timestamp data attributes, and timestamp-named classes, but collects observations before stabilization and has no rule for visible clock text. The generated desktop Blog screenshot contains `CURRENT TIME: 02:58:39 BST`; another state records a different time, and randomized archival headings are also persisted.

Apply deterministic masking or normalization to both pixels and structured text for this external handoff. If that cannot be done safely, record the volatility as a limitation instead of claiming reproducible masked evidence, and verify it with a rerun/manifest assertion.
