# Blog masking rewrite, script type-checking scope, and sound-gate disclosure (v3)

This pass re-verifies the three Important findings from the prior review of Task 1's behavioral-baseline capture pipeline: incomplete Blog volatility masking, scripts/tests sitting outside `tsc`'s type-checked surface (with a real ES2020/ES2021 lib mismatch), and a `desktop-sound-gate` reference state that silently duplicated `desktop-pointer`. All three were re-verified against current file contents and a freshly regenerated current-site capture run, not just the test suite: the Blog masking rewrite (two-sample diff plus a persistent `MutationObserver`) produces `[MASKED DYNAMIC HEADING]`/`[masked dynamic text]` consistently across all four applicable states in a fresh run, `tsconfig.scripts.json` gives the automation code its own ES2021 type-check surface without touching `tsconfig.json` or `npm run build`, and the sound-gate duplication is now disclosed in both docs as a known, unfixed duplication rather than silently patched away. Watch for: **likely** the new volatility mask matches heading/paragraph elements by array index between two `querySelectorAll` samples taken 350ms apart, which could mis-mask or miss content if the surrounding element count on the page changes between the two samples — contained to the Blog route only, and not observed to misfire against the live target in this run.

**Verdict**: APPROVED

## High-level view

The Blog masking gap is closed. The old one-shot regex against `h1/h2/h3` text is replaced with a two-sample diff across `h1, h2, h3, p` that flags any element whose text changed between samples (plus a loosened `/^ARCH/i` heuristic as a backstop), and both that mask and the separate timestamp mask now re-apply themselves continuously via `MutationObserver` for the rest of the page's lifetime instead of running once. A fresh `npm run test:baseline` run regenerated `artifacts/baseline/current/manifest.json` and its screenshots from the live Blog redirect target, and all four applicable states now show the placeholder text with no live glitch text leaking through; the screenshots confirm stable content around it — `REF: XERO-DEV-07`, `Class: ARCHIVAL`, the `ARCH LINUX KERNEL 6.18` system line, and the card lists — is untouched.

The type-checking gap is closed cleanly. `tsconfig.scripts.json` is a standalone config with no `extends` relationship to `tsconfig.json` and a disjoint `include`, so it doesn't affect `npm run build`, which still only type-checks and bundles `src`. `tsc --noEmit -p tsconfig.scripts.json` passes with 0 errors, resolving the `replaceAll` ES2021 dependency in `capture-current.ts`.

The `desktop-sound-gate` duplication is disclosed, not silently fixed. Both docs now state plainly that the reference `desktop-sound-gate` state is a byte-identical rerun of `desktop-pointer`'s silent-path audit and should not be read as independent confirmation of a distinct sound-choice condition. Neither doc claims the underlying code was changed, and it wasn't — `createCapturePlan`'s gap logic is still `target === 'current' && state.soundGate` only, so the duplication itself remains; that's consistent with rerunning the preserved reference capture being out of scope here.

Two of the three new regression tests are genuinely non-trivial and would fail against the prior one-shot regex: the continuously-regenerating-heading fixture runs on an 80ms interval and asserts correct masking after a 500ms wait, and the re-rendering-clock fixture runs on a 90ms interval with a 700ms wait. The third is the original static-content test carried over unchanged.

No regressions surfaced. The full 20-test suite passes, `npm run build` and `npm run typecheck:baseline` both succeed, `npm run lint` still fails only with the pre-existing missing `eslint.config.*`, and `artifacts/baseline/reference/manifest.json` is untouched (`generatedAt: 2026-07-20T21:43:55.454Z`, 20 captured / 15 blocked), confirming the public reference capture was not rerun.

### Blog volatility masking: two-sample diff replaces the one-shot regex

`maskVolatileDynamicText` (`capture-current.ts:275-330`) samples `h1, h2, h3, p` text twice, 350ms apart, and marks any index whose text differs between samples — or matches the broadened `/^ARCH/i` heuristic on either sample — as volatile, then keeps a `MutationObserver` running for the rest of the page's life so further regeneration before the eventual screenshot gets re-masked. `maskTimestampText` got the same persistent-observer treatment for the visible-clock case, and now runs for every subject rather than just Blog.

The regenerated manifest is the strongest evidence: `desktop-pointer`, `mobile-touch`, `desktop-keyboard`, and `desktop-reduced-motion` Blog records all report the heading as `[MASKED DYNAMIC HEADING]` — previously only `mobile-touch` got this by timing luck, and `desktop-keyboard` carried a different unmasked glitch string each run. The screenshots confirm the heuristic isn't over-broad: `REF: XERO-DEV-07`, `Class: ARCHIVAL`, and the `ARCH LINUX KERNEL 6.18` line all render untouched, because none of them sit inside an `h1/h2/h3/p` that changed between samples or starts with `ARCH`.

The fragility in the rewrite is the positional-index correlation between the two samples (`capture-current.ts:296-306`): `firstSample[index]` is compared against `secondSample[index]` with no anchor beyond `querySelectorAll` ordering. If the Blog target ever renders a different number of `h1/h2/h3/p` elements between the two samples — a lazy-loaded block, an ad, a conditionally-rendered banner — every index after the change point would be compared against the wrong element. This is contained to the Blog subject, the only caller of this function, and the whole point of the fix is resilience against a target whose DOM changes out from under the capture, so it's worth flagging even though it didn't manifest here.

### tsconfig.scripts.json: strictness parity, no build interaction

The new config mirrors the main config's chosen strictness flags (`strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`) rather than loosening any of them; the only meaningful difference is the ES2021 `lib`/`target`, which is the fix's actual purpose. A search of `scripts/`, `tests/`, and `playwright.config.ts` for other ES2021-only APIs (`replaceAll`, `Object.hasOwn`, `.at()`) found only the known `replaceAll` calls in `escapeHtml`, so this isn't masking a second undetected gap.

### Sound-gate duplication: documented, not fabricated as fixed

`createCapturePlan` (`tests/fixtures/viewports.ts`) still computes the current-target gap flag as `target === 'current' && state.soundGate` with no reference-target branch, so nothing in code makes `desktop-sound-gate` behaviorally distinct for the reference target. The doc updates in both files state this directly and match what `reference/manifest.json` actually contains, rather than describing a fix that isn't there.

### Regression tests: two exercise real failure modes, one is inherited

The heading/paragraph test exercises a case the prior code never covered at all — it only masked `h1/h2/h3`, never paragraphs — and its 500ms wait against an 80ms regeneration interval would expose a one-shot mask immediately. The clock test runs against the `home` subject specifically, isolating the general timestamp mask from the Blog-specific diff logic, with a 700ms wait against a 90ms tick. The third test (`normalizes volatile current handoff text before observation and capture`) is the original static-content test, unmodified; it confirms the rewrite didn't regress the simple case but adds no new coverage.
